# Loop record — The smtp package

The `smtp` package sends a message through an account whose credential the `imap` package keeps in the macOS Keychain. `send.py <name> <message-file>` is its script, and `/smtp send` its command. The feature record is `2026-11-13T08-22-43Z-smtp-package`.

**Mode:** unattended. The engineer chose it in the request, and accepted the plan before any code was written.

## 1. Actuation

- **Hinge:** the shape of the send at its use site.
- **Decision:** `slasher/system/smtp/send.py work-mail some-message.eml`, run from the project root. The account is named as `fetch.py <name>` names it, so one name serves the fetch and the send. The message is a file, since the agent writes it and the engineer can read it before the send.

## 2. Observation

- **Hinge:** which effects of the send the test reads.
- **Decision:** the test SMTP server writes what it received to files: the sender, the recipients, and the message. The test reads those. The sender and the recipients are the envelope, which the message's own headers do not show. Bcc recipients are in the envelope and not in the message, so both are read.

## 3. Controls

- **Hinge:** the situation the test needs.
- **Decision:** a keychain file of the test's own, with one credential written by imap's `credential.sh`, as the imap tests do. A local SMTP server in `test/automated/smtp/controls/server.py`, in plain text, with `SMTP_PORT` and `SMTP_TLS=no`, as the imap tests use `IMAP_PORT` and `IMAP_TLS`. A message file with To, Cc, and Bcc, no From, and the line of dashes a fetched message has.

## 4. Implementation

- **Hinge:** the code that satisfies the test, written directly or by red/green/refactor.
- **Decision:** written directly, on the Python standard library's `smtplib`, as `fetch.py` is on `imaplib`. The login and host come from `security find-generic-password -l <name>`, which prints no credential. The credential comes from imap's `credential.sh read --name`, so the package uses imap's store and does not copy its code.
- **Decision:** the SMTP host replaces a leading `imap.` with `smtp.`. It is a policy of the package's own, so it has a test. The test uses a `.invalid` host, which never resolves, and reads the host named in the failure.
- **Decision:** a name with no credential fails with a message naming it, in a file of its own.

## 5. Naming

- **Hinge:** the outcome names.
- **Decision:** the files follow imap's: `send.sh` for the normal path, `send-host.sh` for the host, and `send-without-stored-credential.sh` with the context *When no credential is stored under the name*. The outcomes in `send.sh` name what the send does: *Sends from the account's login*, *Sends to every To, Cc, and Bcc recipient*, *Adds a From header with the login*, *Leaves the Bcc header out of the message*, *Sends the body without the separator line*.

**Outcome:** the four smtp tests pass, with `deactivated.sh` beside them. The automated suite passed: 57 tests. Committed on `feature/worktree/smtp-package`.
