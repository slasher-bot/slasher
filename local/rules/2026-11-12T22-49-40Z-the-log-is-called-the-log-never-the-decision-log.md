# The log is called the log, never the decision log

**As the engineer stated it:** The term "decision log" should not be used. It's just "log".

1. Call the project's record in `slasher/local/logs/log/` the **log**, and one file in it a **log entry**.
2. Do not write "decision log", in a record, a commit message, or an answer to the engineer.
3. Do not write a phrase that reads as "decision log". *The publish decision's log entry* reads as one. Write *the log entry for the publish*.
4. An entry tagged `[decision]` is still a log entry, in the log. The tag names what the entry records, not a separate log.
5. A historical record that says "decision log" stays as written.

**Why:** the log holds more than decisions: a state that changed, a finding, why work was abandoned. "Decision log" narrows the reader's idea of the log to one kind of entry. The rules stopped saying it on 26 October 2026, but only in their History sections, which are not read at session start. So the term came back in the agent's answers.

**How to apply:** where a sentence names the log or one of its entries, name it **the log** or **the log entry for** what it records. Read the phrase back as the engineer would, and rewrite it where "decision" stands next to "log".
